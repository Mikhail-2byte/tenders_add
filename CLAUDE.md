# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Локальная программа тендерного менеджера «Тендеры»: читает из буфера обмена список тендеров, скопированный из 1С (поля через табуляцию), вставляет **новые** тендеры в `заметки.xlsx` (лист «Лист1»), создаёт папки `C:\Работа\В работе\<Номер>\С ЭТП`, проставляет гиперссылку «Открыть» в столбце «Папка» и ведёт статистику добавлений по дням.

Два модуля: `add_tenders.py` (ядро, вся логика) и `tender_app.py` (GUI на tkinter). Комментарии, вывод и общение с пользователем — на русском.

## Запуск

- Обычный сценарий: ярлык «Тендеры» на рабочем столе (запускает `pyw -3.12 tender_app.py` с иконкой `Тендеры.ico`) или `Тендеры.bat` — открывает окно программы без консоли. Вкладка «Добавление»: кнопки «Предпросмотр» (dry-run, ничего не меняет) и «Добавить тендеры». Вкладка «Статистика»: сводка (сегодня/7 дней/30 дней/всего), график по дням и таблица.
- Ядро из консоли (для отладки): `py -3.12 add_tenders.py [--dry-run] [--file ПУТЬ]`. GUI тоже принимает `--file` — удобно проверять на копии.
- Зависимость: `openpyxl` (см. `requirements.txt`); GUI и буфер обмена — встроенный tkinter.
- Тесты: `py -3.12 -m pytest` из корня (конфиг в `pyproject.toml`: `testpaths = tests`, `pythonpath = .`); зависимости — `requirements-dev.txt`.

## Важные особенности

- **Путь к рабочему xlsx не зашит в код**: `load_xlsx_path()` читает `config.json` рядом со скриптом (пишется кнопкой «Изменить…» в окне), иначе берёт `DEFAULT_XLSX` — `%USERPROFILE%\Desktop\заметки.xlsx`. Ключ `--file` — разовая подмена, в `config.json` не сохраняется.
- Файл Excel должен быть закрыт при боевом запуске — проверяется открытием в режиме `r+b` (в dry-run проверка пропускается).
- **Защита данных**: перед сохранением оригинал копируется в подпапку `backups` рядом с xlsx (хранятся последние `BACKUP_KEEP` = 10 копий); запись атомарная — во временный `.tmp`, затем `os.replace` на оригинал.
- Журналы рядом со скриптом: `add_tenders.log` (человекочитаемый итог запусков) и `history.jsonl` (JSON-строка на каждый боевой запуск — источник статистики).
- Автофильтр листа расширяется на добавленные строки.
- Вся конфигурация — блок констант в начале `add_tenders.py`: `WORK_DIR`, `SHEET`, `DEFAULT_XLSX`/`CONFIG_PATH`, индексы столбцов `COL_*`, множество `STATUSES`, форматы дат `DATE_FORMATS`, цвет подсветки `HIGHLIGHT_RGB`, `BACKUP_KEEP`.
- Локальные файлы (`config.json`, `add_tenders.log`, `history.jsonl`, `backups/`, `*.xlsx`, `.claude/`) в git не попадают — см. `.gitignore`. Репозиторий публичный: не коммить реальные данные тендеров и личные пути.

## Архитектура

**Ядро (`add_tenders.py`)** — функция `sync(xlsx_path, text, dry_run, say)`: принимает текст буфера, возвращает dict с итогами (`new`, `existed`, `created_folders`, `linked`, `backup`); ожидаемые проблемы (файл открыт/не найден, буфер пуст, строки не распознаны) поднимает как `SyncError` с готовым текстом для пользователя; весь вывод — через колбэк `say(*args)`. Статистика: `record_history` / `load_history` / `counts_by_day`.

**GUI (`tender_app.py`)** — класс `TenderApp`: `sync` выполняется в `threading.Thread`, сообщения в UI идут через `queue.Queue` + `root.after` (tkinter не потокобезопасен); буфер читается в главном потоке через `clipboard_get`. `SyncError` → `messagebox.showwarning`. График — столбики на `tk.Canvas` за последние `CHART_DAYS` = 14 дней, без внешних библиотек.

## Как работает ядро

**Разбор буфера** (`parse_row`): поля разделены TAB; `number` = поле 4, `customer` = поле 5, `deadline` = поле 2 (форматы с временем и без, см. `DATE_FORMATS`). Номера нормализуются (`norm_number`: неразрывные пробелы → обычные). ЭТП и комментарий ищутся через «якорь-статус»: первое поле, совпадающее с множеством `STATUSES`, затем статус+1 = ЭТП, статус+2 = комментарий (fallback — фиксированные индексы 10/11). Разбор покрыт тестами в `tests/test_parse_row.py`, ядро `sync()` — в `tests/test_sync.py` (вставка в нужное место, сохранность существующих строк, папки, подсветка, бэкап, dry-run).

**Стратегия «снимок и перезапись»**: скрипт снимает полный снимок каждой существующей строки данных (значение + стиль + гиперссылка + примечание, `snapshot_cell`/`apply_snapshot`), очищает всю область данных и записывает всё заново. Новые тендеры вставляются сразу после своей строки-«якоря» — предыдущего тендера из списка 1С, чтобы сохранить порядок 1С. Ручные данные существующих строк (Ссылка, Наименование, комментарии и т.д.) не изменяются. Это осознанный выбор: `insert_rows()` в openpyxl не переносит стили/гиперссылки.

**Подсветка**: новые строки получают оформление строки-якоря (`apply_style_only`) плюс светло-зелёную заливку `C6EFCE`; подсветка прошлого запуска при этом снимается — зелёным выделены только тендеры текущего запуска.

**Папки**: `find_existing_folder` ищет папку по точному имени `<номер>` или по префиксу `<номер> …`/`<номер>_…`. `ensure_folder` создаёт `<Номер>\С ЭТП` только для тендеров из текущего списка 1С; для старых строк ссылка ставится, только если папка уже существует.
