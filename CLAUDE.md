# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Локальная программа тендерного менеджера «Тендеры»: читает из буфера обмена список тендеров, скопированный из 1С (поля через табуляцию), добавляет **новые** тендеры в `заметки.xlsx` (лист «Тендеры»), создаёт папки `C:\Работа\В работе\<Номер>\С ЭТП`, проставляет гиперссылку «Открыть» в столбце «Папка» и ведёт статистику добавлений по дням.

Рабочий лист — умная таблица `Тендеры_база` из 12 столбцов (A Заказчик, B Наименование тендера, C Номер, D Ссылка, E ЭТП, F Окончание подачи, G Комментарий, H Действие, I Статус, J Контакты, K Папка, L Сорт.). При каждом боевом запуске лист **пересортировывается целиком**: сначала по группе статуса (справочник на листе «Справочники»), затем по сроку подачи. Новые тендеры получают статус «В работе» и сами встают наверх — работа идёт сверху вниз.

Пакет `tenders/`: `core.py` (ядро, вся логика) и `app.py` (GUI на tkinter), точка входа — `__main__.py`. Комментарии, вывод и общение с пользователем — на русском.

## Структура

```
tenders/     core.py (ядро), app.py (GUI), __main__.py (точка входа)
assets/      Тендеры.ico — иконка окна и ярлыка
```

## Запуск

- Обычный сценарий: ярлык «Тендеры» на рабочем столе (указывает на `Тендеры.bat`, иконка `assets\Тендеры.ico`) или сам `Тендеры.bat` — делает `cd` в корень и запускает `pyw -3.12 -m tenders`, окно без консоли. Вкладка «Добавление»: кнопки «Предпросмотр» (dry-run, ничего не меняет) и «Добавить тендеры». Вкладка «Статистика»: сводка (сегодня/7 дней/30 дней/всего), график по дням и таблица.
- Ядро из консоли (для отладки): `py -3.12 -m tenders.core [--dry-run] [--file ПУТЬ]` из корня проекта. GUI тоже принимает `--file` — удобно проверять на копии.
- Зависимость: `openpyxl` (см. `requirements.txt`); GUI и буфер обмена — встроенный tkinter.
- Тесты: `py -3.12 -m pytest` из корня (конфиг в `pyproject.toml`: `testpaths = tests`, `pythonpath = .`); зависимости — `requirements-dev.txt`.

## Важные особенности

- **Путь к рабочему xlsx не зашит в код**: `load_xlsx_path()` читает `data/config.json` (пишется кнопкой «Изменить…» в окне), иначе берёт `DEFAULT_XLSX` — `%USERPROFILE%\Desktop\заметки.xlsx`. Ключ `--file` — разовая подмена, в `config.json` не сохраняется.
- Файл Excel должен быть закрыт при боевом запуске — проверяется открытием в режиме `r+b` (в dry-run проверка пропускается).
- **Защита данных**: перед сохранением оригинал копируется в подпапку `backups` рядом с xlsx (хранятся последние `BACKUP_KEEP` = 10 копий); запись атомарная — во временный `.tmp`, затем `os.replace` на оригинал.
- Журналы в `data/`: `add_tenders.log` (человекочитаемый итог запусков) и `history.jsonl` (JSON-строка на каждый боевой запуск — источник статистики). Пути считаются от `ROOT_DIR` (корень проекта = родитель пакета), папка создаётся при записи через `ensure_parent_dir`.
- **Макет листа фиксирован**: перед записью `check_layout()` сверяет строку заголовков с `HEADERS` и при расхождении отказывается работать. `sync()` стирает всю область данных, поэтому ошибка в раскладке столбцов стоит слишком дорого.
- После перезаписи пересчитываются границы умной таблицы (`ref`, `autoFilter.ref`, `sortState.ref`), диапазоны условного форматирования и жёстко зашитые диапазоны `Тендеры!…$749` в формулах «Дашборда» и листов-витрин (`widen_formulas`). Автофильтра у самого листа нет — он принадлежит таблице.
- Вся конфигурация — блок констант в начале `tenders/core.py`: `WORK_DIR`, `SHEET`/`REF_SHEET`/`TABLE`, `ROOT_DIR`/`DATA_DIR`, `DEFAULT_XLSX`/`CONFIG_PATH`, индексы столбцов `COL_*` и `NCOL`, `HEADERS`, `SORT_FORMULA`, `DEFAULT_STATUS`, `DEADLINE_FORMAT`, множество `STATUSES_1C`, форматы дат `DATE_FORMATS`, `BACKUP_KEEP`.
- Локальные файлы (`data/`, `backups/`, `*.xlsx`, `.claude/`) в git не попадают — см. `.gitignore`. Репозиторий публичный: не коммить реальные данные тендеров и личные пути.

## Архитектура

**Ядро (`tenders/core.py`)** — функция `sync(xlsx_path, text, dry_run, say)`: принимает текст буфера, возвращает dict с итогами (`new`, `existed`, `created_folders`, `linked`, `backup`); ожидаемые проблемы (файл открыт/не найден, буфер пуст, строки не распознаны) поднимает как `SyncError` с готовым текстом для пользователя; весь вывод — через колбэк `say(*args)`. Статистика: `record_history` / `load_history` / `counts_by_day`.

**GUI (`tenders/app.py`)** — класс `TenderApp`: `sync` выполняется в `threading.Thread`, сообщения в UI идут через `queue.Queue` + `root.after` (tkinter не потокобезопасен); буфер читается в главном потоке через `clipboard_get`. `SyncError` → `messagebox.showwarning`. График — столбики на `tk.Canvas` за последние `CHART_DAYS` = 14 дней, без внешних библиотек.

## Как работает ядро

**Разбор буфера** (`parse_row`): поля разделены TAB; `number` = поле 4, `customer` = поле 5, `deadline` = поле 2 (форматы с временем и без, см. `DATE_FORMATS`). Номера нормализуются (`norm_number`: неразрывные пробелы и переводы строк → обычный пробел, повторы схлопываются). ЭТП и наименование ищутся через «якорь-статус»: первое поле, совпадающее с множеством `STATUSES_1C`, затем статус+1 = ЭТП, статус+2 = наименование (fallback — фиксированные индексы 10/11). Сам статус 1С в результат не попадает: в Excel у новой строки всегда `DEFAULT_STATUS`. Разбор покрыт тестами в `tests/test_parse_row.py`, ядро `sync()` — в `tests/test_sync.py`.

**Сопоставление номеров**: в столбце C встречаются ячейки с двумя номерами через перевод строки — `numbers_in_cell` разбивает их, иначе такие тендеры добавлялись бы повторно.

**Стратегия «снимок и перезапись»**: `sync` снимает полный снимок каждой существующей строки (значение + стиль + гиперссылка + примечание + высота, `snapshot_cell`/`apply_snapshot`), очищает всю область данных и записывает всё заново в новом порядке. Гиперссылка снимается объектом целиком, а не через `.target`: у части ссылок адрес лежит в `location`. Ручные данные существующих строк (Ссылка, Наименование, комментарии, Действие, Контакты) не изменяются — меняется только положение строки. Это осознанный выбор: `insert_rows()` в openpyxl не переносит стили/гиперссылки, а сортировать средствами openpyxl нечем.

**Сортировка** — ключ `(группа статуса, срок подачи, исходный порядок)`. Группы читаются с листа «Справочники» (`load_groups`, C2:C11 → E2:E11); статус вне справочника даёт `UNKNOWN_GROUP` = 99 и уезжает вниз. Срок: `datetime` → серийное число, `int/float` как есть, пусто и текст → в конец группы. Третий элемент ключа делает сортировку предсказуемой: при равных группе и сроке старые строки остаются на местах, новые встают следом.

**Оформление новой строки** (`build_template`): по каждому столбцу берётся первая строка данных **без заливки** — иначе утащили бы остаточную «зебру» `E8EEF7`. Заливка новой строки явно пустая: фон белый, цвет даёт условное форматирование по статусу и сроку. Признак «добавлено сейчас» — не цвет, а текст `Добавлен ДД.ММ.ГГГГ` в столбце «Действие».

**Дата в столбце F**: значение пишется первым, `number_format = DEADLINE_FORMAT` — только после. При обратном порядке openpyxl не считает кастомный формат `[<1]"";…` датой и затирает его своим, из-за чего ломается `ISNUMBER($F2)` в условном форматировании.

**Что openpyxl теряет при сохранении**: выпадающий список статусов (он в расширении x14 внутри `<extLst>`), веб-надстройка, настройки печати, кэши формул. Список статусов возвращается вручную: `read_ext_lst` снимает фрагмент из исходного файла до правки, `write_ext_lst` вшивает его во временный `.tmp` до `os.replace`. Из фрагмента обязательно вырезается `xr:uid` — иначе префикс `xr` окажется необъявленным и Excel сочтёт файл повреждённым. **Не удаляйте эту постобработку как «лишнюю»** — без неё пропадает проверка данных в столбце «Статус». Остальные потери безвредны или невосполнимы: openpyxl ставит `fullCalcOnLoad`, поэтому формулы Excel пересчитывает сам.

**Папки**: `find_existing_folder` ищет папку по точному имени `<номер>` или по префиксу `<номер> …`/`<номер>_…`. `ensure_folder` создаёт `<Номер>\С ЭТП` только для тендеров из текущего списка 1С; для старых строк ссылка ставится, только если папка уже существует.
